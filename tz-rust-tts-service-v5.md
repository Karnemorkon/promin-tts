# Технічне завдання та план розробки сервісу озвучення (TTS / Audio Studio) на мові Rust

## 1. Вступ та мета проєкту

Метою проєкту є розробка продуктивного, нативного та безпечного сервісу для генерації мовлення (Text-to-Speech) та озвучення довготривалого контенту (аудіокниг, підкастів, відеороликів, навчальних матеріалів), з підтримкою **гібридної архітектури** (локальна робота або поділ на легкий клієнт та потужний сервер), максимальної **апаратної сумісності** (робота на серверах без GPU, підтримка процесорів з AVX без обов'язкового AVX2) та безшовного розгортання в **Docker** для систем автоматизації (n8n, Make, Node-RED) і голосових асистентів (**Home Assistant / Wyoming Protocol**).

Проєкт будується повністю на мові **Rust** з залученням нативних C++/CUDA/ONNX рушіїв (zero Python у рантаймі) для досягнення максимальної швидкодії, низького використання пам'яті, локальної автономності (Local-first) та легковажності контейнерів.

При проектуванні використано та синтезовано архітектурні рішення та нативні моделі з п'яти ключових джерел:
1. **Speech Studio** (timoncool/speech-studio) — нативна структура на Rust (Tauri 2 + Axum), пряма робота з книжковими форматами (EPUB/FB2/DOCX), генерація M4B з главами, стандартизація гучності ACX (-16 LUFS) та контроль якості через зворотне розпізнавання (Back-ASR).
2. **Voicebox** (jamiepine/voicebox) — багатотрековий редактор історій ("Stories editor"), нарізка довгого тексту з плавним кросфейдингом (0–200 мс), ланцюжки аудіоефектів (DSP), асинхронна черга генерації та протокол MCP.
3. **HolosTTS-hybrid** (Karnemorkon/HolosTTS-hybrid) — алгоритми текстової автовербалізації числівників/дат/часу, наголошування, потоковий WebSocket/REST синтез, **Docker-контейнеризація для CPU** та сумісність з **Home Assistant (Wyoming)**.
4. **holos-tts-core** (Karnemorkon/holos-tts-core) — C++20/ONNX Runtime інференс без Python, портативне розгортання в Docker та використання надшвидких префіксних дерев `marisa-trie` для словників наголосів.
5. **Holos Native Models** (Morkon/holos-native-models on Hugging Face) — оптимізовані нативні INT8 ONNX моделі генерації, компактні Gemma-3-270M та M2M100 вербалізатори, нейро-наголошувач `accentor-lite.onnx` та префіксний тривіальний словник `stress.trie`.

## 2. Загальна архітектура системи (System Architecture)

Сервіс будується за модульним принципом у вигляді монорепозиторію Rust (Cargo Workspaces) з можливістю чіткого розмежування клієнтської та серверної частин:

```
rust-voice-studio/
├── crates/
│   ├── speech-core/        # Бізнес-логіка, управління проєктами, черга генерації
│   ├── speech-text/        # Текстовий препроцесинг: нормалізація, вербалізація (Gemma-3/M2M100), наголоси (marisa-trie)
│   ├── speech-inference/   # C ABI обгортки для ONNX Runtime (ort) та GGUF/C++ (GPU / CPU AVX / AVX2)
│   ├── speech-audio/       # DSP-обробка, ефекти, кросфейдинг, LUFS-нормалізація, FFmpeg
│   └── speech-server/      # Web-сервер на Axum (REST, WebSocket, OpenAI API, Wyoming, MCP, Auto-Downloader, Webhooks)
├── desktop/                # Легковажна оболонка Tauri 2 (Rust) + SPA (React / TS) [Thin Client / Local GUI]
├── deploy/                 # Dockerfile (CPU AVX / CPU AVX2 / GPU CUDA), docker-compose, Helm charts
└── Cargo.toml
```

### Режими розгортання (Deployment Modes):

1. **Standalone Local Mode (Все-в-одному)**:
   - GUI-додаток (Tauri 2) запускає локальний процес бізнес-логіки та нейромережевого інференсу безпосередньо на ПК користувача. Призначено для потужних робочих станцій з відеокартами NVIDIA/DirectML чи Apple Silicon.
2. **Remote Client-Server Mode (Розділений режим / Слабке залізо)**:
   - **Серверний бекенд (`speech-server` + `speech-inference`)**: розгортається на будь-якому віддаленому сервері, хмаровому VPS без GPU, домашньому NAS або Docker-контейнері. Автоматично адаптується під наявне залізо (GPU CUDA, CPU AVX2, CPU AVX fallback).
   - **Клієнтський фронтенд (Tauri 2 Desktop GUI або Web SPA)**: запускається на слабкому пристрої користувача (ноутбук без GPU, планшет, слабкий ПК). Фронтенд здійснює лише відображення UI/таймлайну та надсилає текстові/проєктні дані на сервер через WebSocket / REST API з аутентифікацією (API Key / JWT).

## 3. Технічне завдання (ТЗ)

### 3.1. Функціональні вимоги

#### А. Обробка та підготовка тексту (Text Pipeline)
1. **Імпорт книжкових та текстових форматів**:
   - Підтримка форматувального імпорту: `EPUB`, `FB2`, `PDF`, `DOCX`, `TXT`, `Markdown`.
   - Автоматичний парсинг структури книги: глави, підрозділи, анотації.
   - Виділення прямих реплік та діалогів (автоматичне визначення персонажів за шаблонами `Автор: ...`, `Анна: ...`).
2. **Лінґвістичний препроцесинг та нативний стек моделей (`Morkon/holos-native-models`)**:
   - **Автовербалізація**:
     - *Основна нейро-модель*: `verbalizer/gemma-int8/` (~227 MB) — квантована Gemma-3-270M-uk ONNX INT8 з KV-caching для зверхшвидкого розгортання чисел, дат, часу та валют у текстову форму ("250 грн" → "двісті п'ятдесят гривень").
     - *Legacy / Fallback моделі*: `verbalizer/onnx-int8/` (~764 MB, M2M100-418M INT8) та `verbalizer/ct2-int8/` (CTranslate2 fallback).
     - *Правила/C++ регулярки*: ультра-швидкий бекап без залучення нейронних мереж.
   - **Автонаголошування**:
     - *Словниковий наголос*: `stress/stress.trie` (~180 MB) — надшвидкий пошук за префіксним деревом `marisa-trie` (понад 2.9 млн слів і форм).
     - *Нейро-наголос (OOV fallback)*: `accentor/accentor-lite.onnx` (~70 MB) — компактна ONNX модель для розстановки наголосів у рідкісних та несловникових словах.
     - *Розмітка*: підтримка наголошування символом `+` або Unicode Accent (`U+0301`).
   - **Користувацькі словники вимови**: можливість задавати регулярні вирази, заміни та фонеми для специфічних термінів чи власних назв.
   - **Підтримка розмітки мовлення**: опрацювання паузи (`[pause 500ms]`, `sil<[300]>`), зміни темпу (`[rate:1.2]`) та емоційних тегів.

#### Б. Генерація та управління голосами (Voice Engine & Profiles)
1. **Бібліотека голосів та ONNX Генератор**:
   - *ONNX Генератор*: `tts/holos_cpu_int8.onnx` (~1.1 GB INT8 ONNX модель з `vocab.json` та `voices.json`), що забезпечує 24 кГц високоякісний синтез.
   - Створення профілів голосів на основі короткочасних референсних аудіозаписів (Zero-shot Voice Cloning) із збереженням 256-мірних векторних ембеддінгів.
   - Підтримка 27+ пресетних голосів та можливість фільтрації за тегами (стать, вік, мова, тембр).
2. **Асинхронний конвеєр генерації (Async Pipeline)**:
   - Асинхронна черга завдань без блокування UI з відображенням прогресу в реальному часі (SSE / WebSocket).
   - Інтелектуальне розбиття довгих текстів на сегменти з перекриттям і зведенням кросфейдом (Crossfade 0–200ms).
   - Збереження проміжних версій генерації (Takes) із можливістю A/B порівняння та перегенерації окремих речень.

#### В. Багатотрековий редактор та робота з підкастами ("Stories / Timeline")
1. **Розподіл ролей**:
   - Призначення окремих голосів для диктора/автора та кожного персонажа в книзі або підкасті.
2. **Мультитрековий таймлайн**:
   - Графічний таймлайн для перегляду та редагування накладання голосів, фонової музики та звукових ефектів.
   - Редагування пауз між репліками, обрізка та вирівнювання часових міток.

#### Г. Інтеграції для автоматизації, Home Assistant та Remote Client-Server
1. **Розділений режим "Клієнт — Сервер" (Thin Client / Remote Inference)**:
   - Перемикання в налаштуваннях GUI: "Локальний сервер" або "Дистанційний бекенд (IP:Port)".
   - Потокова передача прогресу генерації та аудіо-попереднього перегляду (Audio Streaming Preview) зі віддаленого сервера на тонкий клієнт без затримки.
   - Синхронізація проєктів (`.speechproj`): можливість вибору локального зберігання або віддаленого збереження проєктів на сервері.
   - Авторизація за допомогою API-ключів (API Key) та безпечне з'єднання (HTTPS / WSS).
2. **Інтеграція з Home Assistant (Wyoming Protocol)**:
   - Вбудована підтримка Wyoming TCP/socket протоколу для використання як системного TTS-сервісу в Home Assistant.
   - Автоматичне виявлення в мережі (mDNS / Zeroconf) або пряме підключення IP:Port.
   - Підтримка передачі параметрів голосу, мови та темпу через стандартизовані події Wyoming.
3. **Системи автоматизації (n8n, Make, Node-RED)**:
   - **REST API ендпоінти**:
     - `POST /v1/tts/synthesize` — швидкий синтез коротких повідомлень/сповіщень у форматах WAV/MP3/OGG.
     - `POST /v1/projects/generate-async` — фонова асинхронна генерація аудіокниг чи підкастів з поверненням `job_id`.
   - **Webhooks**: підтримка реєстрації HTTP Webhook callback-ів для сповіщення зовнішніх платформ про готовність обробки великих файлів.
4. **Протокол MCP (Model Context Protocol)**:
   - Сервер MCP для надання можливостей синтезу, клонування голосів та озвучення текстів автономним AI-агентам (Claude, Cursor, AutoGPT).

#### Д. Контроль якості (Quality Control - Back-ASR)
1. **Автоматична верифікація озвучення**:
   - Зворотне розпізнавання аудіо за допомогою компактної ASR-моделі (Whisper / Parakeet).
   - Покомпонентне зіставлення розпізнаного тексту з оригінальним скриптом для підсвічування пропущених чи спотворених слів.
2. **Аудіо-діагностика**:
   - Автоматична перевірка на наявність кліпінгу, занадто довгих пауз, артефактів або стороннього шуму.

#### Е. Експорт та формати виходу
1. **Аудіокниги**:
   - Експорт у формат **M4B** з вбудованою метаінформацією про глави та обкладинкою.
   - Можливість експорту окремими файлами по главах або за персонажами.
2. **Підкасти та відео**:
   - Експорт у форматі WAV, MP3, FLAC, OGG.
   - Генерація субтитрів: `SRT`, `VTT`, `ASS` із синхронізацією по словах.

### 3.2. Нефункціональні вимоги, крос-платформеність та завантаження моделей

1. **Динамічне завантаження моделей (Auto-Downloader)**:
   - Сервер розгортається без заздалегідь вбудованих важких моделей у Docker-образ.
   - Модуль `downloader` при першому запуску автоматично виявляє відсутні файли та завантажує необхідні вагові моделі з Hugging Face (`Morkon/holos-native-models`) безпосередньо у монтований `named volume` / кеш-директорію (`models/`).
   - Базовий набір моделей для запуску займає лише **~0.6–1.1 GB** (за замість 20+ GB у традиційних Python-стеках).
2. **Гнучкість інструкцій CPU та відсутність вимог до GPU**:
   - **Підтримка серверів без GPU**: стабільна робота нейромережевого інференсу виключно на CPU без необхідності дискретних відеокарт чи спеціальних драйверів.
   - **Сумісність зі старими/бюджетними CPU (AVX без AVX2)**:
     - Модуль `speech-inference` збирається з універсальним фолбеком для x86_64 інструкцій **AVX** (v2 baseline) без примусової вимоги **AVX2 / BMI2 / FMA**.
     - Динамічне автовиявлення наборів інструкцій CPU (SIMD dispatching) під час запуску: використання AVX2 або AVX-512 при наявності, або авто-перехід на базові AVX/SSE4.2 кернелі без падіння процесу (`SIGILL`).
   - **Квантування моделей (INT8 / Dynamic Quantization)**: використання оптимізованих INT8 моделей ONNX для забезпечення швидкого синтезу навіть на слабких процесорах з базовим AVX.
3. **Контейнеризація (Docker & Docker Compose)**:
   - Багатоетапна збірка (Multi-stage Dockerfile) для мінімізації розміру підсумкового образу (<200 MB без вагових моделей).
   - Варіанти Docker-конфігурацій:
     - `docker-compose.cpu-legacy.yml`: для застарілих серверів / VPS з інструкціями **AVX** (без AVX2).
     - `docker-compose.cpu-modern.yml`: оптимізований під сучасні CPU (AVX2 / AVX-512).
     - `docker-compose.gpu.yml`: під підтримку NVIDIA GPU (NVIDIA Container Toolkit, CUDA/TensorRT).
   - Клієнтський режим без GUI (Headless mode) — можливість розгортання як чистий мікросервіс на Linux VPS / Kubernetes.
4. **Вимоги до клієнтського пристрою (Thin Client)**:
   - При використанні віддаленого сервера мінімальні вимоги до пристрою користувача: будь-який CPU (x86_64 / ARM64), від 2 GB RAM, відсутність дискретної відеокарти (GUI споживає <100 MB RAM).
5. **Продуктивність**:
   - Використання 100% Rust для бізнес-логіки та C++/CUDA/ONNX C ABI для нейромережевого інференсу.
   - Швидкість синтезу: 10x-15x RTF на GPU, 2x-5x RTF на AVX2 CPU, 1.2x-2x RTF на AVX CPU.
6. **Конфіденційність (Local-first & On-Premise)**:
   - Усі обчислення, текстові дані та голосові ембеддінги обробляються виключно на сервері/локальному пристрої користувача без передачі в сторонні хмари.
7. **Кросплатформеність**:
   - Подтиримка ОС: Linux (Debian, Ubuntu, Alpine uClibc/musl), Windows 10/11, macOS (Intel / Apple Silicon ARM64).
   - Апаратне прискорення: NVIDIA CUDA, ONNX Runtime Execution Providers (CPU, CUDA, DirectML, OpenVINO).

## 4. Етапи та план розробки (Roadmap)

### Етап 1: Текстовий модуль та препроцесинг (`speech-text`)
- [ ] Реалізація парсерів книжкових форматів (`EPUB`, `FB2`, `PDF`, `DOCX`).
- [ ] Інтеграція модуля автовербалізації чисел/дат/часу на основі Gemma-3-270M INT8 ONNX (`verbalizer/gemma-int8/`) та C++ правил.
- [ ] Інтеграція наголошування: гібридний словник `stress.trie` (marisa-trie) + нейро-наголошувач `accentor-lite.onnx`.
- [ ] Написання модулів розбиття тексту на речення з урахуванням пунктуації та спеціальних тегів.

### Етап 2: Нативний інференс моделей, сумісність AVX та аудіо-конвеєр (`speech-inference` & `speech-audio`)
- [ ] Налаштування C ABI зв'язки з ONNX Runtime (`ort` crate) для завантаження `holos_cpu_int8.onnx` із сумісністю з AVX CPU без AVX2.
- [ ] Реалізація динамічного вибору SIMD-кернелів в інференсі (CUDA → AVX-512 → AVX2 → AVX fallback).
- [ ] Реалізація голосового кодера (Voice Encoder) для зняття та збереження 256-мірних ембеддінгів голосу.
- [ ] Розробка аудіо-процесора: кросфейдинг сегментів, алгоритми DSP (Pitch, Reverb, Compression).
- [ ] Реалізація нормалізації гучності LUFS (EBU R128) та True-Peak лімітера.

### Етап 3: Сервер, Auto-Downloader, інтеграція Docker (AVX/AVX2/GPU), Wyoming, Client-Server та автоматизації (`speech-server`)
- [ ] Розробка асинхронного сервера на Axum (REST, WebSocket, OpenAI `/v1/audio/speech`).
- [ ] Реалізація модуля `auto-downloader` для прозорого завантаження моделей з `Morkon/holos-native-models` (Hugging Face).
- [ ] Реалізація авторизації (API Keys) та мережевого протоколу для віддаленого тонкого клієнта (Thin Client WebSocket Streaming).
- [ ] Реалізація протоколу **Wyoming** для Home Assistant.
- [ ] Реалізація ендпоінтів автоматизації (REST API для сповіщень, асинхронна генерація, Webhooks для n8n/Make).
- [ ] Інтеграція протоколу MCP для зовнішніх AI-агентів.
- [ ] Написання Dockerfile (Multi-stage build) та складання `docker-compose` конфігурацій під AVX, AVX2 та GPU.

### Етап 4: Проєктна система, таймлайн, Back-ASR та GUI (`speech-core` & `desktop`)
- [ ] Розробка структури проєкту (`.speechproj`) та синхронізації між клієнтом і віддаленим сервером.
- [ ] Розробка мультитрекового двигуна для генерації підкастів та діалогів.
- [ ] Реалізація модулів експорту в M4B (із главами), WAV/MP3 та субтитри SRT/VTT.
- [ ] Створення модуля Back-ASR верифікації (авто-перевірка розпізнаванням після генерації).
- [ ] Збірка десктопного інтерфейсу на Tauri 2 + React/TypeScript (підтримка вибору рендерингу: "Local Rust Backend" або "Remote Axum Server").
